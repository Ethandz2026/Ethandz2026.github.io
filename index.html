01 · ARCHITECTURE

大致结构：五层，一个入口

编排层只认识一个地址。请求带着 machine 参数进入边缘网关，鉴权后沿各自的加密隧道落到目标节点；节点之间再通过内网互相取数、交接产物。

LAYER 1编排层

理解需求、拆成子任务，按「能力标签」挑节点，最后汇总结果并验收。它不直接碰硬件，只发 MCP 调用。

LAYER 2接入层

边缘聚合网关：单一入口、统一鉴权，把一份工具清单扩展成「同一套工具 × 三台机器」，并提供节点在线探测。

LAYER 3传输层

每台机器一条出站加密隧道，令牌逐跳隔离；机器不开任何入站端口，换网络、出门在外也照样在线。

LAYER 4执行层

三台节点上的 MCP 服务：读写文件、执行命令、管理进程。Windows 走 PowerShell，Linux 走 bash，开机或登录即自启。

LAYER 5数据层

Git 与共享目录承载任务单、中间产物和日志。Agent 之间不靠「记忆」交接，而靠可检查的文件。

02 · NODE STRENGTHS

扬长避短：每台机器只干最擅长的

三台机器的硬件差异很大。与其让每台都「什么都干一点」，不如按长板给它们定岗：重算力归台式机，高并发归新笔记本，长时间值守归 Linux 小机器。

04 · SWARM

集群作业：长板如何接力

以一次典型的「资料调研 → 生成内容 → 发布」任务为例：编排层拆单，三台机器各接一段，产物以文件形式交接，最后由另一台机器交叉验收。

拆解

编排层把需求拆成子任务，写入共享任务单，标注每段需要的能力。

编排层

采集

多路并行抓取网页与资料，清洗成结构化文本落盘。

LENOVO

生成

本地模型做摘要、向量化与配图生成，大文件直接存在本机。

ETHAN

验收

跑校验脚本与回归检查，结果写回任务单；不过关就打回重做。

XIAOMI

交付

合并产物、提交 Git、触发发布；值守节点持续监控上线状态。

全体

扇出 / 汇聚FAN-OUT · FAN-IN

同一类任务切成多份，同时派给多台机器，完成后由编排层合并。适合批量抓取、批量处理。

流水线接力PIPELINE

上一段的输出就是下一段的输入：采集 → 生成 → 验收。每台机器只做自己最快的那一段。

交叉验收MAKER · CHECKER

「做」和「验」分在不同机器、不同 Agent 上，避免自己检查自己。验收不过的产物会带着原因退回。

值守与接管WATCHDOG · FAILOVER

常驻节点定时探测其他节点；某台离线或卡住时，任务按路由表降级到备选节点继续跑。

零入站端口

全部走出站隧道，家里路由器不做任何端口映射。

令牌逐跳隔离

入口一把钥匙、节点各一把，任何一段泄露都不连坐。

开机即上线

计划任务与 systemd 用户服务自启，断电重启后自动回归集群。

一切可追溯

任务单、产物、日志都落成文件，出了问题能回放每一步。
